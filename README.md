# claude-usage-check

チームの **Claude Code と Codex の使用量** を、メンバーの PC から1つの共有フォルダ（Google ドライブ・OneDrive など）に集めて、担当者が **PDF レポート** にするための道具です。

**このリポの URL を Claude Code または Codex に渡して「使用量を送って」と頼むと**、必要なことを聞きながら進めます。

## 何を集めて、何を集めないか

| 集めるもの | 集めないもの |
|---|---|
| 日付ごとのセッション数・人の発言数・AI の応答数 | 会話の中身（プロンプト・返答・ファイル） |
| モデル別のトークン数（Codex は推論も含む）と Claude Code の API 換算額（目安） | パスワード・API キー・アカウント情報 |
| 起動元（CLI・IDE など）の回数、任せ度、作業時間、自動実行の割合、曜日と時刻ごとの発言数 | 作業していたファイルの名前 |
| スキル・エージェント・MCP・コマンドの呼び出し回数、ファイル編集回数 | スキルの内容、コマンドの内容 |
| 入っているスキル・エージェント・プラグインの数、整備されたフォルダ数、`CLAUDE.md`・`AGENTS.md` の有無と行数、フック・MCP 設定の数 | ハーネスの名前・パス・設定内容 |
| （担当者が希望した時だけ）Claude Code の作業フォルダ名ごとの発言数。呼んだスキル・エージェント・MCP などの名前も共有 | Codex の作業フォルダ名。既定では道具の名前をハッシュにして種類だけを区別 |

- 数字は **手元の Claude Code のログ**（`~/.claude/projects/`）と **Codex のログ**（`~/.codex/sessions/`）から数えます。`CLAUDE_CONFIG_DIR`・`CODEX_HOME` でそれぞれの設定フォルダを指定できます
- **インターネットには何も送りません**。書き込む先は、手元の設定ファイル（`~/.claude-usage-check/config.json`）と、利用者が指定した同期フォルダだけです
- Python 3.9 以上の標準機能だけで動きます（追加のインストールは不要）
- 任せ度は AI の応答数 ÷ 人の発言数です。作業時間は同じセッション・同じ日で5分以内の記録間隔を足して求めます。Codex の自動実行の割合は起動元を判別できる場合に表示します。自動レビューはターン数とトークンを別集計し、モデル別にも表示します
- 対象はローカルの使用ログです

## 担当者がやること

1. **共有フォルダを1つ作る**（例: Google ドライブに「Claude使用量」）。メンバー全員を **編集者** で共有する
   - メンバーの PC には Google ドライブ（パソコン版）か OneDrive が入っていて、そのフォルダが同期されている必要があります
   - メンバー同士でお互いの数字が見えます。見せたくない場合は、メンバーごとに別のフォルダを作って担当者にだけ共有してください
2. **メンバーに案内を送る**（下の文面を使えます）
3. **月末にレポートを作る**。Claude Code または Codex に、このリポの URL と「使用量のレポートを作って」と頼む。手で実行する場合は次のとおりです:
   ```
   python3 usage_check.py report --dest "<共有フォルダ>" --org "会社名" --from 2026-11-01 --to 2026-11-30
   ```
   共有フォルダの `claude-usage/reports/` に HTML と PDF ができます（PDF の書き出しには Chrome か Edge が要ります）
4. 金額を円で見たい場合は `--yen 150` のように 1ドルあたりの円を付けます（report・export）
5. **スプシで見たい場合**は `python3 usage_check.py export --dest "<共有フォルダ>" --from ... --to ...` で CSV が同じ場所にできます。月別・フォルダ別などの表に加え、`codex`・`work`・`heatmap`・`harness` が出ます。`--json` を付けると標準出力に JSON が出ます

### メンバーへの案内文（ひな形）

> Claude Code と Codex の使用量を月に1回集めます。会話の中身は集めません。
> 1. 共有フォルダ「〇〇」があなたの PC で見えることを確認してください（Google ドライブのパソコン版）
> 2. Claude Code または Codex を開いて、次の文を貼ってください:
>    `https://github.com/yujirotn/claude-usage-check/blob/v0.5.0/CLAUDE.md を読んで、使用量を送って。格納先は共有フォルダ「〇〇」`
> 3. 毎月最終営業日に、同じ文を貼ってください

## メンバーがやること

Claude Code または Codex に次の文を貼ると進められます。初回だけ、名前と格納先を聞かれます。

```
https://github.com/yujirotn/claude-usage-check/blob/v0.5.0/CLAUDE.md を読んで、使用量を送って
```

## 手で実行する場合

```bash
git clone https://github.com/yujirotn/claude-usage-check && cd claude-usage-check && git checkout v0.5.0
python3 usage_check.py find-drives                              # 同期フォルダの候補
python3 usage_check.py setup --name "山田" --dest "<共有フォルダ>"  # 初回だけ
python3 usage_check.py retention --days 90                      # 初回だけ・任意（下の注意）
python3 usage_check.py collect                                  # 毎月
```

Windows では `python3` を `py` に読み替えてください。

## 注意

- **Claude Code は既定で30日より古いログを消します**。月に1回の送信で取りこぼさないよう、`retention` でログを残す日数を90日に延ばすことを勧めます（`~/.claude/settings.json` の `cleanupPeriodDays`。元のファイルは `.bak-usage-check` として残します）。その分ディスクの使用量は増えます
- 同じ日の数字は送るたびに上書きされるので、何度送っても二重には数えません。ログが消えた古い日の数字は、共有フォルダ側に残ります
- 「API 換算」は Anthropic API の公開単価（`prices.json` に記載の時点）で計算した Claude Code の目安です。Codex はトークン数で表示します
- セッションは始まった日に数えます。「AI の応答」にはサブエージェントの応答も含みます
- **数字は自己申告です**。共有フォルダの編集者は誰でもファイルを書き換え・削除できるので、改ざんは仕組みの上では防げません。正確さが要る場合は、メンバーごとに別のフォルダにして担当者にだけ共有してください
- report は共有フォルダの JSON の形を確かめ、合わないファイルは集計から外して「注意:」と表示します。HTML には外部の読み込みを止める設定（CSP）を入れています
